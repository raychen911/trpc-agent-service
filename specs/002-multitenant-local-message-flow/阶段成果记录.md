# 第二阶段成果记录：多租户本地消息闭环

## 背景与目标

第一阶段只证明官方 tRPC-Agent SDK 的 Runner、Event 和 Session 能离线运行。本阶段把
它放入一个可验证的平台纵向链路：本地 HTTP → HMAC Binding → Gateway → 租户隔离 →
幂等/会话锁 → Worker → 官方 Runner → 统一回复 → Audit/Metrics。

## 完成内容

- 两个演示租户、Agent 和独立 Channel Binding，秘密只从运行时环境解析。
- tenant+agent+binding+channel+user+conversation 派生会话身份，同租户多轮连续，跨租户
  session、SDK user、审计伪名和指标隔离。
- `(tenant_id, binding_id, external_message_id)` 幂等状态机；100 次顺序重复和 20 组
  并发重复均最多执行一次。
- 同会话串行、不同会话并行；prepare 前失败可重试，RUNNING 后超时/取消不可重放。
- 成功、拒绝、重复、冲突、Agent 失败、审计失败和终态不确定的稳定回复、trace 与审计。
- Repository/Adapter Protocol 与 InMemory 实现分离，并用最小 Fake Adapter 验证替换边界。
- `trpc-agent-local-serve` 和 `trpc-agent-local-send`；仅允许 loopback，客户端不继承系统
  代理，避免本地签名请求被代理转发。

## 人工决策

重点评审并批准 D-001–D-008：会话串行；按 Agent 开始边界决定重试；每 Binding 独立
HMAC；TenantScope/PreAuthScope；最终审计先于幂等终态；超时/取消结果未知；Agent 属于
SessionIdentity；current/owner/execution trace 分工。判断原则是默认拒绝、避免副作用
重放、显式租户作用域和失败可见。详细依据见 `决策记录.md`。

## 实现与测试结果

最终分类结果为 unit 36、contract 27、integration 20、SDK baseline 18；全量
`101 passed in 4.19s`。真实 Uvicorn 进程完成 health、双租户、多轮、重复和冲突演示，
耗时不足 1 分钟。实际演示发现 CLI 继承系统代理导致本地请求得到空 502，修复为
`trust_env=False` 后通过，这一过程体现了自动化测试之外仍需真实运行验收。

## 答辩演示重点

1. alpha 保存并召回 ALPHA，beta 使用相同外部用户/会话保存并召回 BRAVO。
2. 展示两个不同 session_id，说明租户和 Agent 已进入身份摘要。
3. 重发同一消息得到 `duplicate/suppress`，original_trace_id 指向首次执行。
4. 同 ID 改正文得到 409；错误签名得到统一 401，且 Worker/Session 无副作用。
5. 展示审计查询、MetricsSnapshot、故障注入测试以及 D-001–D-008 追踪表。

## 已知限制与下一阶段

当前仅单进程 InMemory 和确定性离线模型，重启后状态丢失，不代表跨节点 exactly-once。
未包含真实企业微信、Redis、SQL、向量库、生产 Telemetry、Kubernetes 或管理后台。
下一阶段可保持现有端口和契约测试，替换共享幂等/锁/Session/Audit 后端，再接入真实 IM
验签与异步回复。
