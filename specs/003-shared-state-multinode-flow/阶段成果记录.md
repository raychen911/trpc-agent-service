# 第三阶段成果记录：多节点共享状态消息闭环

## 阶段目标

把第二阶段单进程 InMemory 链路扩展为两个独立 Worker 可验证的共享状态链路，并保持
HTTP、Gateway、官方 tRPC-Agent Runner 和统一回复契约不变。Redis 承担 Session、
幂等与租约；PostgreSQL 承担权威配置、持久审计和恢复标记。

## 人负责确认的五项关键决策

| 决策 | 判断与取舍 |
|---|---|
| D-003-001 租约续期 | 只接受 Redis 判断仍未过期且 token+generation 匹配的续期；不用 Worker 本机时钟。 |
| D-003-002 fencing | 旧 generation 的业务写全部拒绝；由当前平台身份另写不可变诊断审计。 |
| D-003-003 节点接管 | 只有共享证据明确处于 EXECUTION_STARTED 前才重放；未知即 outcome_unknown。 |
| D-003-004 部分提交 | PostgreSQL 同事务保存 final Audit+TERMINAL_PENDING，再做 Redis CAS；恢复器只补终态，不调用 Agent。 |
| D-003-005 配置缓存 | PostgreSQL 是授权权威；正缓存不能在 SQL 不可用时放行，选择安全失败关闭。 |

这些决策体现 AI Native 协作中的人工责任：AI 负责展开方案和生成验证，人负责在安全、
一致性与可用性之间选择边界，并要求每个选择都有可复现测试证据。

## 实现结果

- 两个独立 CLI Worker 可在不同端口启动，无 sticky session；节点退出后另一节点继续会话。
- Redis Lua 原子实现 message claim、Session lease、续期/释放、generation 和 fenced Session 写。
- PostgreSQL 保存 Tenant/Agent/Channel Binding、不可变 Audit、RecoveryMarker；初始化可重复执行。
- 相同消息跨节点至多一个 owner；相同会话串行、不同会话并行；旧 generation 不可写。
- 配置或共享状态不可用时不回退 InMemory，统一返回脱敏、稳定错误。
- InMemory 与 Redis 幂等实现运行同一厂商无关契约；共享 Session 直接实现官方 BaseSessionService。

## 测试与证据

- 最终全量：165 passed in 31.67s（真实 Redis/PostgreSQL，零跳过、零失败）。
- 官方 SDK 定向回归：18 passed in 3.73s。
- 200 次随机跨节点路由：p95 45.57ms，0 错误，200 次 Agent 执行。
- 幂等：100 次顺序重复、50 组双节点并发，每组只有一个 Agent 授权分支、一份事件结果和一次可投递结果。
- 租约：50 个同会话竞争峰值为 1；20 组不同会话均观察到并行。
- 故障：执行前/执行后各 20 次 owner 租约失效；前者均换代接管，后者均 outcome_unknown 且不重放。
- 重启恢复：20 组 Session、幂等终态和 Audit 在全部 Worker 对象重建后均可继续或查询。
- 部分提交：SQL 已提交而 Redis CAS 失败时，恢复器只复制既有结果，Agent 调用新增数为 0。
- 详细 RED→GREEN 命令、修订原因与结果见 `validation-results.md`。

## 边界声明

本阶段仅是本地双节点与单 Redis/PostgreSQL 的一致性验证，不包含真实企业微信、向量库、
Kubernetes、管理后台、真实模型 API、生产级 Telemetry、跨地域 HA 或生产 exactly-once。
