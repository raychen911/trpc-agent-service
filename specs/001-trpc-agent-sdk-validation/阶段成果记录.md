# 第一阶段成果记录：tRPC-Agent SDK 最小集成验证

**阶段日期**：2026-09-04
**功能编号**：`001-trpc-agent-sdk-validation`
**对应总体验收项**：README 验收标准 7——明确区分 tRPC-Agent-Python 复用能力与平台新增能力

## 1. 阶段定位

本项目最终目标是设计和实现一个多租户、可节点化部署、支持多后端和 IM 接入的
Agent 平台。本阶段不直接开发完整平台，而是先验证最基础的技术前提：项目能否真正
使用官方 tRPC-Agent-Python SDK 完成 Agent 执行、事件输出和多轮 Session。

这一步为后续 Gateway、Worker、多租户隔离和存储适配提供可运行的框架基线，避免
后续设计建立在未经验证的 SDK 假设上。

## 2. 阶段目标

- 固定并验证 `trpc-agent-py==1.1.19`。
- 真实经过官方 `LlmAgent → Runner → Event → InMemorySessionService` 链路。
- 在没有真实 API Key、没有外部模型调用和费用的条件下运行。
- 验证单轮回复、同 Session 上下文连续性和不同 Session 隔离。
- 提供可重复执行、可自动判断、可定位失败阶段的 CLI 和测试证据。

## 3. 实现方案

```text
固定测试消息
    ↓
DeterministicValidationModel（仅替代外部大模型）
    ↓
官方 LlmAgent
    ↓
官方 Runner
    ↓
官方 Event + InMemorySessionService
    ↓
七阶段 Human / JSON 验证报告
```

关键设计：

- 使用确定性 `LLMModel` 子类替代真实模型供应商，但 Agent、Runner、Event 和
  Session 均使用官方 SDK，未伪造被验证的框架链路。
- 同时检查发行包元数据和 SDK 版本模块，防止只检查一个版本来源造成误判。
- 使用两个 Session，每个 Session 执行两轮；第二轮只能从 SDK 提供的历史中读取
  第一轮 token，模型自身不保存会话状态。
- 使用 `Event.is_final_response()` 和 `Event.get_text()` 判断最终回复，而不是简单
  取最后一个事件。
- 报告固定包含七个阶段，支持 human 和 JSON 输出，以及成功、验证失败、参数错误
  三类退出码 `0/1/2`。
- 测试时清除常见模型凭据、阻断外部 socket，并扫描 stdout/stderr，防止秘密泄露。

三类故障注入均能定位到正确阶段：

- SDK 版本不匹配 → `version / version_mismatch`；
- 没有最终 Event → `event_finalization / final_response_missing`；
- Session 上下文丢失 → `session_continuity / context_missing`。

## 6. 实施中发现并解决的问题

- SDK 顶层包没有 `__version__`：改为从正式版本模块读取，并与发行包元数据双重核对。
- Windows `asyncio` 会使用本机回环 socket：网络守卫调整为允许 loopback、只阻断
  外部连接，避免把运行时内部机制误判为外部模型请求。
- Human 输出最初使用 `PASSED`：按 CLI 契约统一为 `PASS/FAIL/SKIPPED`，并将测试
  从子串匹配改为整行匹配。
- 多个 CLI 子进程导致测试超过目标时间：改为复用正式 `main()` 入口进行进程内契约
  测试，在不减少断言的情况下将测试耗时降至 10 秒以内。

## 7. 答辩演示方式

在项目根目录执行：

```powershell
uv sync --group dev
uv run python -m trpc_service.agent.sdk_validation
uv run python -m trpc_service.agent.sdk_validation --json
uv run pytest tests/sdk_validation -q
```

演示时重点说明：

1. 最终 `RESULT: PASS` 和七阶段 PASS；
2. 实际 SDK 版本为 1.1.19；
3. `event_count=4`、`final_response_count=4`；
4. `credential_required=false`、`external_model_calls=0`；
5. pytest 显示 18 项测试全部通过。

## 8. 阶段结论与边界

本阶段已经证明：作业仓库能够稳定复用 tRPC-Agent-Python 的 Agent、Runner、Event
和 Session 能力，并具备离线、可重复、可诊断的自动化验证基线。

本阶段没有实现或验证生产级多租户、Gateway、IM Adapter、Redis/SQL、跨节点状态
和部署拓扑；这些属于后续功能阶段，不能用本阶段结果代替生产能力证明。

详细数据见 [validation-results.md](./validation-results.md)，运行说明见
[quickstart.md](./quickstart.md)。
