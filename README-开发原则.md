# 开发原则

1. 不保留向后兼容。过时的直接删除，不加兼容层，不写 migration，不留 fallback。

2. 选择能满足当前需求的最简单实现。不要做预防性抽象，不要增加多余的配置层。

3. 系统分层生长。先跑通一个最小的端到端版本，再逐步增加能力。绝不为了尚未完成的复杂设计，拆掉已经能运行的部分。

4. 组件保持模块化，关注点分离。

5. 优先使用成熟且有人维护的库。没有明确理由，不要自行重写。

6. 先检查项目现有依赖能够做什么，再考虑增加新包或自行实现。不要一开始就假设现有库没有所需能力。

7. 架构决策按长期方案设计。不接受“先这样，以后再换”的临时方案。

8. 先研究成熟产品如何解决同类问题，采用已经验证的模式，不要从零发明。

9. 不要编写过多没有必要的防御性代码。只处理当前明确的需求、真实存在的边界和已经确认的失败场景；不要为臆测风险增加额外的哈希、兼容层、fallback、冗余校验或多层封装。必要的安全与正确性约束必须保留。
