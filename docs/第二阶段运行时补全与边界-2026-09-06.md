# 第二阶段运行时补全与边界

本记录对应“使用最新官方 SDK，补齐工具、六类后端、迁移灰度、观测”的实施。此前方案中的待实现清单，应结合本记录阅读。

## 官方 SDK 核验

核验来源为 `https://github.com/trpc-group/trpc-agent-python.git` 的远程 HEAD/main；返回提交为 `f05797d9f9dff2461922b5985aeccc1b636b7c8d`，版本 `1.1.20`。它与项目原有依赖固定值相同，因此没有虚构一次版本升级。运行时及测试入口继续检查安装来源，拒绝本地 fork。

该提交原生 Redis/SQL `append_event`、`update_session` 仍不接收平台 fencing token 或 expected revision。平台 SessionCoordinator 的事务只能保护平台表，不能把原生 SDK 写入变成原子 CAS。因此生产模式门禁继续保留；模拟模式的自动恢复验收不代表“任意时刻杀死旧 Worker 后都可无条件重放外部副作用”。

真实迁移测试暴露了原生 SQL 异步读取的 `MissingGreenlet` 问题：读取路径刷新 TTL 后访问了 ORM 的失效字段。服务使用官方公开的同步 SQL 模式，GuardedSessionService 在后台线程执行其公开方法，保留事件循环处理心跳；没有改写 SDK 私有实现。SQL/Memory 明确配置 `expire_on_commit=False`，Memory 仍使用其异步接口。

### 工具接线

数据库配置模式下实际提供 `read_artifact`、`write_artifact`、`search_knowledge`。应用 `tool_policy.allow` 决定可见工具；要求确认的工具不会被自动开放。SDK RunConfig 同时限制模型调用轮数和工具调用数，SQL 台账约束跨重试的调用预算。

模型不能传入 tenant_id、user_id 或 session_id 来切换存储范围。文件身份从可信 InvocationContext 中构造；知识检索强制租户、允许的知识库及固定索引版本过滤。

`search_knowledge` 当前接收**预先计算的向量**；它是实际 Qdrant 检索，不是已完成的自然语言 embedding/RAG 产品。不能让模型随意生成浮点数组冒充语义向量。接入真实 embedding 服务时必须登记模型身份、维度与索引版本；当前模拟模型不会调用外部付费模型。

自定义 Python 业务函数可经 `DurableTools.wrap` 接入官方 FunctionTool。业务幂等键为 `execution_id:function_call_id`，从可信上下文获取。未知结果保持 `unknown_outcome`，只有业务 `recover(key, args)` 确认结果后才能补记完成，不能因网络超时就再次执行扣款、下单等操作。已有工具结果属于业务数据，存入 `tool_results`；审计只保存标识和决策，不保存工具参数或正文。

### 六类资源装配

完整装配使用数据库配置模式。Session/Summary 绑定同一后端和版本；Memory 使用独立原生 SQL 数据库；Artifact 使用对象存储加平台 SQL 元数据；Knowledge 使用 Qdrant；Audit 按其独立 SQL profile 构造。

所有连接信息来自操作员登记的 `env://` 引用。对象存储选项只有 bucket、secure、access_key_ref、secret_key_ref；向量选项只有 collection、index_version、embedding_id。类型、后端类别及凭据引用均校验。其他连接协议没有静默降级。

平台审计和业务台账在平台数据库内事务提交；独立 Audit profile 可接收运行时存储就绪审计。它目前不是平台全部审计表的异库复制服务。配置管理 API 仍是平台操作员接口，并非租户 RBAC 产品。

原文件配置模式保留基础模拟验收用途；要运行上述完整资源组合，使用管理模式。新数据库必须先运行 `migrate`；新增表包括工具结果、灰度分流、维护状态及持久化迁移任务。`create_schema` 不会替已有不兼容的表补列，`check_schema` 会拒绝不兼容结构。

## 部署与初始化

1. 构建镜像并执行平台 `migrate` 初始化任务。
2. 执行 `init-resources`，建立或检查 Qdrant 集合。示例环境使用 2 维向量，仅供确定性验收；已有集合维度不匹配会失败，不会覆盖索引。
3. 按 `后端配置管理运行说明-2026-09-05.md` 设置操作员 token，并使用 `docker-compose.management.yml` 启用管理模式。
4. 通过 `deploy/bootstrap_management.py` 登记并发布首次配置；后续修改创建新 profile/config 版本，不能重复覆盖版本 1。
5. Gateway、两个 Worker、Dispatcher、Post-turn 分别运行，使用共享存储。Collector 接收各进程观测数据。

```powershell
docker compose build
docker compose run --rm migrate
docker compose run --rm init-resources
# 设置 TRPC_ADMIN_TOKEN 后，参照管理运行说明完成首次登记。
docker compose -f docker-compose.yml -f docker-compose.management.yml up -d
```

镜像不包含真实 IM 凭据。导师提供的企业微信 BotID/BotSecret 长连接方式留到第三阶段，见跨对话参考记录。

## 灰度操作

先创建配置草稿，例如当前版本 3、目标版本 4：

```http
POST /admin/tenants/tenant_acme/rollout
Authorization: Bearer <operator-token>
Content-Type: application/json

{"expected_active_version":3,"target_version":4,"percent":10}
```

同一会话在比例不变时稳定落到同一版本。比例递增时分桶顺序不变。修改比例影响后续新消息，已经接收的消息仍消费原固定版本。灰度要求租户状态、应用启用状态、账号路由和存储布局一致。

将 percent 设为 0 可撤回灰度新流量；设为 100 后，调用目标配置的 publish 接口正式切换；发布事务会清除灰度记录。配置回退仍必须满足存储布局一致，避免回到过期的数据副本。

## 数据迁移操作

迁移是**受控离线任务**。维护模式只关闭新消息入口，已接收任务继续排空；它无法阻止一个暂停的旧 SDK 进程稍后写入。执行复制或切换前，必须在部署层停止所有源端、目标端 SDK 写入进程及外部索引写入者。接口中的 `writers_stopped` 是操作员声明，不是自动建立的原子 fence。

1. 登记目标后端/索引的不可变 profile 版本。
2. 创建新配置草稿。storage_revision 必须增加 1；迁移不能同时修改提示词、账号路由等配置。
3. `POST /admin/tenants/{tenant}/maintenance`，正文 `{"enabled":true}`。
4. 等待 Inbox、Memory/Summary 后处理排空；未知执行或失败后处理必须先对账。停止所有相关写入进程。
5. `POST /admin/tenants/{tenant}/migrations`，正文如下；返回 job_id。

```json
{"source_version":3,"target_version":4,"resource_type":"session"}
```

6. 多次调用 `/admin/tenants/{tenant}/migrations/{job_id}/run`：

```json
{"writers_stopped":true,"batch_size":50,"cutover":false}
```

7. `GET /admin/tenants/{tenant}/migrations` 查看 copied/total/status；verified 后用 `cutover:true` 再次全量复核并切换。
8. 重启使用目标版本的服务，关闭维护模式。

源快照在任何目标写入前持久化。目标会话必须初始为空；故障发生在创建或完整写入之后，可以识别自己的中间状态并恢复。切换前同时复核源端和目标端。原生 Session 的当前事件、历史归档、最终状态、conversation_count 都纳入复制。当前业务目录登记的会话是迁移范围；不是任意外部 SDK 数据库的全库搬迁器。

Session 任务只能改变 Session/Summary；Memory、文件、知识与审计的布局保持不变。当前任务拒绝带 `app:`/`user:` 共享状态的 Session，避免把共享状态错误地复制成会话局部状态。共享状态以及 Memory、对象存储、审计数据整体搬迁仍需各自的迁移单元。

知识迁移将 resource_type 改为 `knowledge`，只改变 Knowledge profile revision 和 storage_revision。源目标必须声明相同 embedding_id，集合维度和距离算法一致，并使用更高 index_version；不同 embedding 的重新生成不由本接口自动执行。复制按知识库保存进度，保留删除标记，并拒绝目标额外数据或切换前内容变化。chunk_id 在同一知识库/索引中必须唯一。

切换前可调用 `/abort` 中止并保留源配置，之后关闭维护模式。中止不会删除目标数据。切换后产生了新数据时，禁止仅修改指针“回滚”；应停写后做反向验证迁移到空目标/新索引。旧的 MigrationCoordinator 与 VectorMigration 状态机测试保留为组件验收，不代表原生 SDK 已支持在线双写切库。

## 观测范围

各进程独立初始化 OTLP provider，携带 service.name 和随机 service.instance.id。不替换 SDK 全局 provider；平台追踪不导出 SDK 的原始 prompt、工具参数或异常正文。W3C traceparent 存在 Inbox payload，执行、回复投递和后处理提取同一父上下文；去重 hash 不包含追踪字段。

- `GET /metrics`：本进程采样摘要 + 共享 SQL 的 Inbox/Outbox/Post-turn 积压、最老年龄、活动任务和失败数量。不能把这里的本进程分位数当成所有 Worker 的分位数。
- Collector `http://127.0.0.1:8889/metrics`：所有进程通过 OTLP 上报的计数及直方图，供现有 Prometheus 抓取并聚合。
- `trpc.operation.calls`、`trpc.operation.duration_ms`：Gateway、Worker、Session、文件工具、向量检索、业务工具、Memory、Post-turn、迁移、Outbox。
- `model.first_event_latency_ms`、`model.total_latency_ms`：Runner 可观测的首事件和整体时延；不冒充真实模型流式首 token 延迟。SDK 提供 usage 时才累计 `model.tokens`。
- `sql.command_latency_ms`、`sql.command_errors`：平台 SQL 实际语句耗时与失败数；不导出语句和参数。`trpc.sql.pool` 为 Gateway 平台 SQL 连接池状态。
- `worker.failure`、`worker.session_busy`、`consumer.unavailable`、`tool.unknown_outcome`：实际故障与争用计数。
- `migration.copied`、`migration.verified`、`migration.diff`：复制与复核结果。

Collector 把脱敏追踪写入持久卷 `telemetry-data` 的 traces.json，按 20 MB 滚动、最多 5 个备份、7 天保留。`telemetry-init` 只初始化该卷目录的归属和权限，Collector 以 UID 10001 运行，避免新卷权限导致文件导出失败。示例只暴露本机 Prometheus 抓取端口，未包含公网监控面板、告警通知接收器或 Redis/MinIO/Qdrant 的原生 exporter。完整基础设施告警、真实模型费用及跨全部后台的原生连接池统计，不能以本次平台指标替代。

`deploy/phase-two-alerts.yaml` 提供接入现有 Prometheus 的告警规则。未配置通知目标，不会自动给任何人发送消息。

## 验收结果

最终真实后端回归：**161 passed，0 skipped，61.96 秒**；报告为 `reports/phase-two-runtime-completion-final.xml`。实现文件与新增测试的 flake8 检查通过。该验收覆盖确定性模型与模拟收发；不包含真实模型调用或企业微信/Telegram 的真实通话。

最终镜像已部署到本项目原有的 file/simulation 模式。Gateway、两个 Worker、Dispatcher、Post-turn 全部健康。部署验收发送 16 条新消息，两个 Worker 均参与处理，16 条回复和 32 个后处理任务全部完成；Inbox/Outbox/Post-turn 的积压及失败均为 0。

Collector 实际导出四个进程角色的指标，并确认 **16 条消息都具有完整落盘追踪**：同一 trace_id 关联 gateway.inbox、worker.execute、outbox.send、post_turn.execute。结果记录在 `reports/runtime-deployment-smoke.json`。完整六类资源的数据库配置模式通过独立真实后端 E2E 验证；没有在已有运行环境中更换操作员身份或改动配置来源。

```powershell
docker compose run --rm --no-deps `
  -v C:/Users/32349/trpc-agent-service/reports:/app/reports `
  -v trpc-agent-phase-two_telemetry-data:/telemetry:ro `
  e2e /app/tests/integration/runtime_smoke.py
```

命令中的宿主目录与 Compose 卷名前缀按实际部署修改。观测导出有批处理延迟，验收脚本会等待指标和文件追踪就绪。
