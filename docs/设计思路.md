# 设计思路

## 1. 项目要解决的问题

这个项目不是只运行一个 Agent，而是要提供一个多租户 Agent 服务。平台管理员统一分配模型、凭据和预算；不同租户使用自己的 Agent 与 IM 通道，同时保证数据、权限、密钥和日志互相隔离。

项目已经支持多个 Worker 节点。任意节点都可以处理同一个租户的请求，所以会话不能只保存在本机，也不能依赖 sticky session。

## 2. 设计原则

1. **租户优先**：请求进入系统后先得到 `tenant_id`，后续查询、缓存、工具调用和审计都必须携带租户上下文。
2. **Worker 无状态**：Session、Memory、Summary 和任务状态放在共享后端，Worker 可以直接扩容或替换。
3. **事实边界明确**：Event、State、Inbox、Outbox 和执行状态以 PostgreSQL 为准；Redis 只缓存带版本的近期 Session Snapshot，任何异常都回源 SQL。
4. **重复请求不能产生重复结果**：IM 消息按外部消息 ID 去重，有副作用的 Tool 使用调用账本记录执行状态。
5. **后端可以替换**：业务只依赖 Storage 接口，不直接绑定 PostgreSQL、Redis、向量库或对象存储客户端。
6. **默认拒绝**：跨租户访问、未授权 Tool、危险操作和未知密钥引用默认拒绝。
7. **同一运行语义，两种部署方式**：本地使用主机 Python + uv 和 Compose 基础设施；Kubernetes 使用相同角色与共享状态语义运行完整平台。
8. **所有操作都有脚本入口**：构建、启动、停止、格式化、测试和 Migration 检查由仓库中的 `.sh` 脚本负责。
9. **确认只服务于变更风险**：已授权只读操作直接执行；高风险变更的审批状态写入共享数据库，确认作为新 IM 消息恢复执行。
10. **知识归租户所有**：原始文件、文档版本、Chunk 和向量均以 `tenant_id` 隔离；Agent 只通过版本化 `knowledge_config` 获得指定知识库权限。租户管理员在管理台显式新增、替换和删除，IM 对话者只允许检索。
11. **身份与会话分离**：IM 外部用户、平台 Principal、Conversation 和 Agent Session 分层建模，跨群、跨 Binding 和跨 Tenant 不共享 Session。
12. **恢复必须可证明**：任务 lease generation、Runner Attempt、Checkpoint 和 Tool Ledger 共同判断能否重试；无法证明结果时进入 `UNKNOWN`。
13. **租户管理身份唯一**：每个租户只有一份租户管理员账号和密码；IM 对话者属于渠道身份，不进入后台账号或角色体系。
14. **扩展点先于具体实现**：IM、存储、Workspace 和 Tool 都面向抽象接口；新增 Adapter 复用统一就绪校验、幂等、治理、审计和恢复链路。
15. **运行能力分层**：Tool 是平台内置通用功能，Skill 是平台审核的知识流程，MCP 是租户提供的远程能力；三者都必须显式授权。

## 3. 实现边界

tRPC-Agent-Python 直接负责 `LlmAgent`、`Runner`、模型调用、`FunctionTool`、Skill 仓库/加载器和 MCP 客户端。SDK 的 `InMemorySessionService` 只承载一次请求内的运行视图：平台从 Redis 或 PostgreSQL 取得近期 Session，再按真实 `user/model` 角色恢复；当前问题作为独立新消息执行。跨节点 Session/Memory、RAG、持久队列、治理、审计和 Telemetry 由平台层实现，再通过 Adapter 注入 Runner。

本项目新增以下平台能力：

- TenantContext 和租户隔离；
- Tenant、Agent App、Channel Binding 管理；
- IM 消息标准化、去重和可靠回复；
- 无状态 Worker、Session 路由和执行恢复；
- 多后端 Storage Adapter；
- 工具权限、预算、脱敏、审计和告警；
- 租户管理台、远程 MCP 连接和知识型 Skill 目录；
- 本地期望状态 Worker Pool 与 Kubernetes Scaler。

| 能力 | 直接复用 tRPC-Agent-Python | 本项目负责 |
| --- | --- | --- |
| Agent 执行 | `LlmAgent`、`Runner`、`OpenAIModel`、Agent Event | 租户配置装配、超时、用量和错误恢复 |
| Tool | `FunctionTool` 与模型函数调用 | Capability Grant、审批、Tool Ledger、审计与具体通用 Tool |
| Skill | `FsSkillRepository`、`SkillLoadTool` | 审核目录、租户可见性和 knowledge-only 策略 |
| MCP | `MCPToolset`、Streamable HTTP | 租户连接、密钥、目录固定、网络边界与统一治理 |
| 状态与知识 | 请求内 `InMemorySessionService` | PostgreSQL 完整会话、Redis 近期快照、Memory/Summary、RAG、对象与向量存储 |
| 服务化 | SDK 的 Runner 接口 | FastAPI 控制面、IM Adapter、队列、Telemetry 和运维部署 |

当前代码已完成 Tenant、Agent App、Channel Binding、Agent 核心链路、多后端存储、平台集中模型配置、Usage Ledger、Tool Ledger、持久化审批、结构化日志、配置灰度/回滚、Runner 恢复状态机、Local Workspace，以及企业微信和飞书 Adapter。系统管理台与租户工作台使用独立入口；租户管理员可配置多种 IM、远程 MCP、Skill 授权和版本化 RAG，IM 对话者只使用已授权的 Agent 能力。

当前生产边界是：本地 Compose 和 Docker Desktop Kubernetes 可用于完整验收；正式上线仍需由部署环境提供 TLS、外部 Secret Manager、高可用数据库/对象存储、告警接收端和离机备份。
