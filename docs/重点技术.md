# 重点技术

## 1. 版本选择

版本基线核对日期为 2026-09-10。下表记录当前锁文件或部署清单的实际版本，不把“已锁定”写成“永远最新”。有长期维护分支时优先选用；没有 LTS 通道的组件先固定版本，再通过完整质量门禁升级。

## 2. 多租户隔离

- 当前不可变 `TenantContext` 保存 `tenant_id`、`agent_app_id`、`config_version`、`request_id` 和 `trace_id`；Channel Identity 将平台 Principal、provider identity、Conversation 与 Session 显式关联。
- 所有业务表、缓存键、队列消息、向量 namespace 和对象路径都带 `tenant_id`。
- 数据查询同时匹配租户 ID 和资源 ID，跨租户资源统一返回 404。
- Tool 使用租户白名单和最小权限凭证，密钥只保存 `SecretRef`。
- Tool、MCP、Skill、Workspace 共用 Capability Grant；明确只读的 L0 能力直接执行，L2/L3 变更操作使用持久化 Approval Request，不占用 Worker 等待。
- 租户 IM 与 MCP Secret 由 AES-256-GCM 按记录加密，并按 `channels`、`mcp` 分开作用域；业务配置只保存引用，API 不提供明文读取。

## 3. 幂等和一致性

- IM 消息先写 Inbox，使用 `tenant_id + binding_id + external_message_id` 唯一约束去重。
- Session Event 使用递增序号，State 使用 `version` 做乐观锁。
- Event、State、Inbox 完成状态、Runner Request 和 Reply Outbox 在同一个 PostgreSQL 事务中提交；Runner Attempt、Tool/Usage Ledger 与运行审计使用各自的短事务。当前没有启用 Memory/Audit 派生 Outbox。
- 所有受治理 Tool 先写 Tool Ledger；状态为 `PREPARED/SUCCEEDED/FAILED/UNKNOWN`，成功结果可重放，UNKNOWN 禁止盲目重试。
- 当前不超过 10 MiB 的知识文件由租户管理 HTTP API 同步摄取，并用 `INGESTING/READY/FAILED` 状态恢复；IM Runner 只暴露知识列表和检索 Tool。后续大文件再切换到 Outbox 异步投影。

## 4. 无状态 Worker

- Gateway 先把规范化请求写入 PostgreSQL `agent_task`，成功后才 ACK；唯一键为 `tenant_id + binding_id + external_message_id`。
- 路由键使用 `SHA-256(tenant_id + session_id)`，不能使用 Python 内置 `hash()`。
- 多个 Worker 通过 `FOR UPDATE SKIP LOCKED` 竞争任务；同一 Session 只领取最早未完成任务，租约过期后可由其他节点接管。
- Worker 先按 SQL Claim 返回的 Session version 查询 Redis；精确命中时直接使用近期快照，否则回源 PostgreSQL 并回填缓存。
- 持久历史按 `user/model` 轮次恢复到 tRPC-Agent Session，当前问题只作为一条独立 `user` 消息传入，避免历史与本轮语义混合。
- PostgreSQL 保存 Agent Task、Inbox、完整 Session Event、幂等状态和最终事实；Redis 快照带 Tenant/Agent 隔离键、TTL、事件数和体积上限，故障时 fail-open 到 SQL。
- Worker 崩溃后由其他节点重新消费，数据库版本和 fencing token 阻止旧节点继续写入。
- 任务续租、完成和失败都必须提交当前 lease generation；即使节点 ID 被复用，旧协程也不能修改新租约。
- Worker 每隔 TTL 的三分之一同时续期任务租约与 Session 执行租约，任一失租立即取消旧执行。
- `runtime_node` 保存节点角色、并发度和心跳；管理员通过 `/api/v1/admin/runtime-nodes` 查看 active、stale、stopped 状态。

## 5. 可替换后端

Session、Memory、Summary、Knowledge、Artifact 和 Audit 分别定义接口。Storage Router 根据配置的 Backend Profile 选择实现，上层 Agent 不直接依赖具体数据库客户端。

对象存储统一使用 S3 兼容接口。本地实现为 SeaweedFS 4.44，上层只依赖 `ArtifactStore`，后续可按配置切换到其他 S3 服务。

RAG 原文件保存在配置版本指定的 S3 兼容对象存储，当前本地实现为 SeaweedFS；知识库、Artifact、文档版本和 Chunk 元数据保存在 PostgreSQL，1024 维向量保存在同一 PostgreSQL 的 pgvector。`text-embedding-v4` 按最多 10 条分批调用；重复文件按 SHA-256 幂等，显式更新生成新版本。向量存储按 Tenant 和知识库隔离，Agent 只注册列表和检索工具。新增、替换、删除由租户管理员在 Web 管理台显式操作，页面确认不能代替后端的角色、Agent、知识库授权校验，变更统一写入 Management Audit。

Local Workspace 使用 `WorkspaceProvider` 接入，当前实现保存到 `data/workspaces`。目录按 Tenant、Agent、Request 三层隔离，并在 Worker 执行前注入 Runner Context；两个本地 Worker 使用稳定 Request ID 共享和恢复同一目录，并通过进程间文件租约防止并发执行与活动目录误清理。目录内区分 `inputs`、`outputs`、`tmp`，Tool 只能在授权资源范围内列举或读取有限大小的 UTF-8 文件。本地目录默认保留 7 天并采用有界的机会式清理，避免长期运行后无限占用磁盘。

Skill 直接使用 tRPC-Agent-Python 的 `FsSkillRepository` 和 `SkillLoadTool`。当前采用 knowledge-only 配置，只加载经过审核的步骤说明，不注册 `skill_run`、`skill_exec` 或命令执行能力。

MCP 直接使用 tRPC-Agent-Python 的 `MCPToolset` 和 Streamable HTTP 客户端。租户只配置远程 HTTPS URL、认证类型和写入后不回显的 Bearer Token；工具发现结果固定到连接目录，执行时重新校验租户、连接状态、授权资源、网络地址、超时、Tool Ledger 和审计。租户显式授权后，同时满足 `readOnlyHint=true` 且不存在 `destructiveHint=true` 的 Tool 按 L0 直接执行；未声明、声明冲突或可能写入的 Tool 统一按 L2 确认。目录带风险策略版本，旧目录在首次使用时自动重发现；失败则保守维持 L2，并允许租户管理员手动重试。运行时以刷新后的目录分类覆盖旧 Agent 快照中的风险值，不修改历史版本，也不允许客户端把写操作降级。工具数量、Schema、目录和结果大小均有上限。私网 MCP 默认拒绝，只有平台通过精确主机名白名单显式开放；生产环境还必须使用出口代理或网络策略抵御 DNS Rebinding，应用层 DNS 预检只是纵深防御。MCP 注解属于远端提示而非强制安全边界，对于 GitHub 等支持只读模式的服务，生产连接还应优先使用 Provider 的只读端点或只读 Token 形成服务端约束。

平台内置 Tool 保持通用且受限：`calculate`、`current_time`、`http.get`、`workspace.list`、`workspace.read`、`knowledge.list` 和 `knowledge.search`。其中 HTTP 只允许 Agent 配置的 HTTPS 公网主机，Workspace 只允许当前请求目录内的有限只读访问；租户业务系统通过 MCP 接入，不把针对性逻辑堆入内置 Tool。

## 6. 质量和可观测

- 人员密码使用 Argon2id；浏览器认证使用服务端 Session、HttpOnly Cookie、SameSite 和 CSRF 校验，连续失败触发临时锁定。

- `trace_id` 串联 IM Callback、Gateway、Runner、Model、Tool、Storage 和 IM Reply。
- 日志默认脱敏，不记录 Token、API Key、数据库密码和完整敏感参数。
- Prometheus 从 OTel Collector 读取多进程聚合指标，Metric 不使用 Tenant、Session、User、Request 等高基数标签。
- Grafana 的数据源和 Dashboard 由仓库配置自动初始化，不依赖人工点击配置；低频 Tool 使用所选时间范围内的增量统计，并分别展示调用量、结果和 P95 延迟。
- Python 输出脱敏 JSON 日志并按大小轮转；Alloy 采集后写入 Loki，Grafana 可按节点、级别和 JSON 字段检索。
- 模型用量按请求幂等写入 PostgreSQL Usage Ledger；Prometheus 只保存低基数运行指标。
- Tempo 本地使用单节点文件存储；生产环境需要改为对象存储并按容量设置保留周期。
- `DeprecationWarning`、`PendingDeprecationWarning` 和 `FutureWarning` 在测试中直接视为错误。
- 提交前统一执行格式、Lint、类型、覆盖率、Migration 漂移和 Python 制品构建检查。
