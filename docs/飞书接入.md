# 飞书接入

## 1. 当前范围

飞书作为第二种 IM，使用官方 `lark-channel-sdk 1.4.0` 的 WebSocket 长连接，不需要公网回调。已支持私聊、群聊 `@机器人`、话题线程、文本/Markdown、CardKit 流式卡片、图片和文件。消息写入持久队列后会先发送“正在思考...”可见 ACK，最终文本通过官方 CardKit 接口逐段输出。

```mermaid
flowchart LR
    USER[飞书用户] <--> SDK[Lark Channel SDK]
    SDK <--> CHANNEL[Channel Runtime]
    CHANNEL --> ID[Principal / Conversation]
    ID --> TASK[(Agent Task)]
    TASK --> WORKER[Agent Worker]
    WORKER --> OUTBOX[(Reply Outbox)]
    OUTBOX --> CHANNEL
```

## 2. 配置

在飞书开放平台创建企业自建应用，启用机器人和长连接事件订阅，取得 App ID 与 App Secret。系统管理员创建租户账号后，租户管理员登录 `/tenant`，在“IM 接入”中选择飞书卡片，填写 Agent、App ID、只写 App Secret 和可选的快速响应提示语后启用。

飞书和企业微信的表单都由数据库中的 Adapter JSON Schema 动态生成。飞书卡片必须显示 `app_id` 和 `app_secret`；若升级旧数据库后仍缺少字段，先确认 Alembic 已到当前 Head，再刷新页面，不能退回文件型密钥或硬编码配置。

App ID 保存在 Channel Binding 的非敏感配置中。App Secret 由平台主密钥按租户加密，Binding 只保存内部引用；代码、示例文件和查询响应都不保存或回显真实密钥。Channel Runtime 会在下一轮配置同步时自动建立长连接。

飞书开放平台还需要启用机器人和 WebSocket 事件订阅、订阅消息接收事件，并授予 `im:message`、`im:message:send_as_bot`、`cardkit:card:write` 等权限。权限或事件变更后要重新发布版本并在租户内重新安装应用。

## 3. 平台限制

- SDK 负责 CardKit 创建、更新顺序、限频退避、消息重试和 Provider message ID 去重。
- Binding 的 `streaming=true` 时启用流式文本；可在 `account_config.thinking_message` 修改 ACK 文案，设为空字符串可关闭。
- 流式文本使用官方 CardKit，要求开通 `cardkit:card:write`。
- 群聊默认要求 `@机器人`；线程使用 thread ID 生成独立 Conversation。
- 媒体默认累计不超过 50 MiB，下载后写入租户 Artifact 空间。
- 回复失败由 Delivery Worker 分类；明确失败有限重试，结果未知进入 `UNKNOWN`。
- 撤回能力由 SDK 提供，但 Agent 自动撤回没有业务需求，当前不开放为 Tool。

## 4. 验收

1. 私聊与群聊分别发送消息，确认映射到不同 Conversation。
2. 在话题中回复，确认使用 thread ID 延续 Session。
3. 发送图片和文件，确认 Artifact 只在所属 Tenant 下可读。
4. 重复事件只能生成一个 Agent Task。
5. 停用 Binding 后连接自动断开；重新启用后自动恢复。

联调失败时先检查 Agent 是否启用并绑定活动 Model Profile，再检查 App ID/App Secret、事件订阅、应用发布安装和机器人权限。Agent 就绪、持久队列、失败回复与超时属于共享 Channel/Agent 链路；WebSocket、CardKit、飞书媒体和 Provider 回执属于飞书 Adapter。后续 IM 必须复用共享链路，避免重复出现“配置到消息执行时才失败”的问题。
