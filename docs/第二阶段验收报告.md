## 真实后端与容量样本

干净数据卷启动后，探针输出：

```json
{
  "postgres": "ok",
  "redis": "ok",
  "qdrant": "ok",
  "minio": "ok",
  "workers": 2,
  "capacity": {
    "redis_ping": {"count": 100, "p50_ms": 0.132, "p95_ms": 0.260, "p99_ms": 0.285},
    "sql_select": {"count": 100, "p50_ms": 0.666, "p95_ms": 1.122, "p99_ms": 1.957}
  }
}
```

这是本机 Compose 的连通性/基础延迟样本，不是生产容量承诺。Worker active run、模型首 token/总耗时、token、IM callback、队列 backlog/oldest age、Redis/SQL pool、向量和对象存储延迟均已进入 `REQUIRED_METRICS`；上线前必须在目标模型、真实 IM 峰值和生产资源配额下重新压测。

## 故障与恢复证据

- 重复 callback 只生成一个 execution；相同 ID 不同 payload 被拒绝。
- Inbox、Outbox、Post-turn 的过期 lease 可由新 Worker 接管，旧 owner 不能确认结果。
- 旧 fencing token、过期 lease 和错误 revision 不能写 Session。
- 模型在 partial 输出后超时会记录 `unknown_outcome`，已有部分执行不会盲目重跑。
- Summary 旧水位不能覆盖新水位；任务在 repository 重建后仍可领取。
- 有限重试和 circuit breaker 有自动化测试；Audit 明文 secret 被拒绝。
- 迁移支持 pause/resume/checkpoint/verify/shadow read/cutover/rollback，差异会阻止切换。

## 阶段边界

- 第二阶段使用通道无关的 Inbox/Outbox 和第一阶段 Fake/标准化 Adapter 语义，不宣称真实 IM 账号已经接通。
- Worker 容器验证水平副本、健康检查和 SIGTERM drain；租户 Runner 的动态控制面装载留给后续阶段。
- Compose 凭据仅用于本地验收。生产必须改用 Secret Manager、托管高可用后端、备份恢复、HPA/KEDA、PDB、NetworkPolicy 和跨可用区演练。
