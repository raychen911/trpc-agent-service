# 已知缺陷修复与验收

## 计划与范围

先修复会话迁移的写入顺序与覆盖保护，再修复向量物理主键和内容校验，最后统一正常执行与崩溃恢复的失败状态判定。为原有五项迁移失败和一项运维失败增加边界回归，移除 known_gap 标记，运行本地完整回归和真实后端严格验收。不在本轮扩展生产 Worker、企业微信入口、自动灰度或自动备用模型。

## 实现

| 缺陷 | 调整 | 验收重点 |
|---|---|---|
| MIG-01 旧源覆盖新目标 | 写入前比较完整历史前缀的规范化内容；拒绝更长、分叉或内容变更的目标；相同历史但状态不同，要求提供批准的目标快照摘要 | 拒绝后目标逐字段不变；同 event ID 不同内容不能蒙混通过；过期批准摘要失效 |
| MIG-02 历史 delta 覆盖最终状态 | 先恢复历史，再重新读取目标并保存最终 State 快照 | 独立 update_session 保留；末条事件提交后中断可经检查目标快照后续传 |
| VEC-01 跨租户/索引覆盖 | 使用 tenant、knowledge base、index version、chunk ID 的无歧义 JSON 元组生成稳定 UUID，payload 保留逻辑 chunk ID | 同 ID 跨租户、索引版本和知识库同时存在；支持非 UUID 的逻辑片段 ID |
| VEC-02 只比较数量 | 校验 ID 集合、document ID、正文、metadata、删除状态、向量；切换前重读两侧；校验失败撤销原许可 | 数量相同的内容损坏、额外记录、校验后的源/目标变更均阻止切换 |
| OPS-01 错误被记为成功 | 检查 ERROR 事件，不以 final 代表成功；普通执行、已有 Outbox、已有已提交事件三条路径共享判定；恢复未结束的 attempt | 无工具调用的错误为 failed_final；已发出工具调用后的错误保守记为 unknown_outcome；不再次领取、不盲重放、不派生 Summary/Memory |

模型错误仍生成脱敏后的 Outbox 回复；错误的业务状态和回复投递状态分开。当前通道事件只有通用 agent_error，无法可靠断定工具副作用或重试安全性，因此不会仅凭“看起来像超时”自动重试。完整 deadline、工具账本对账与有条件模型切换仍不在本轮实现范围。

向量按现有知识检索的 cosine 语义校验归一化方向，允许浮点存储误差；并非要求 Qdrant 返回的向量模长与源值完全相等。嵌入模型或维度改变时，正文重新生成向量，含删除标记的记录也使用目标维度；这不等于真实模型的检索质量评测。

## 迁移调用约束

`copy_and_verify_trpc_session` 和 `restore_trpc_session` 默认拒绝写入。调用者必须先停止该目标会话的所有业务及迁移写入，再显式传入 `target_writes_paused=True`。这个参数是操作前提声明，不会自动停止 Worker，也不是分布式锁。

现有 SDK 的公开接口不提供跨读取/追加/更新的 CAS 或整体事务，因此这套复制只用于隔离、停写的目标。目标不能在复制尚未校验成功时向业务提供读取；中断时允许留有未完成历史，由恢复流程处理。源端快照应来自一致读，最终追平及切换需要停写或外部写屏障。

`revision=len(events)` 仅表示当前导出记录的历史长度，不代表可判断独立 State 修改先后的真实版本。相同历史存在 State 冲突时，默认拒绝；调用者检查正确的迁移方向后，传入先前保存的 `expected_target_digest` 批准离线替换。摘要不匹配即拒绝，不在函数内部自动接受新的目标快照。不得据此宣称已实现在线并发迁移或原子跨库回滚。

向量 cutover 同样要求调用方冻结待切换索引，并在部署层原子发布路由；当前对象中的 active_index_version 不是生产路由服务。重新校验可发现两次调用之间的修改，但不能替代底层并发写屏障。

已有 Qdrant collection 不应直接混入新物理 ID：应从可信源重建新 collection/索引、严格校验后切换。被旧主键覆盖的记录无法凭修改代码找回，需要源数据或备份恢复。本轮没有删除或重建用户业务索引，也没有推送 GitHub。

- 四项本地跳过为 MinIO 和三个真实 TCP 故障用例，必须由真实后端验收覆盖。
- 新构建 e2e 镜像，挂载最新工作区源码，在真实 PostgreSQL、Redis、Qdrant、MinIO 上运行完整严格回归：121 passed，无 skip/xfail，耗时 31.54 秒。含原运维故障 6 项全部通过；新增错误恢复边界为另外 6 项。

- CI 的真实后端回归已加 `--strict-acceptance`，不再依赖预期失败标记放行；尚未在远端运行。

原容量报告保留修复前测量条件与数值，不把本次修复推断为容量提升。生产入口、在线迁移、提交各阶段崩溃、真实模型 deadline 与副作用工具对账仍需后续验收。

复现本次严格回归：

```sh
docker compose --profile test build e2e
docker compose up -d --wait postgres redis qdrant minio
docker compose --profile test run --rm --no-deps \
  -v "$(pwd)/reports:/app/reports" e2e \
  -m pytest -o addopts= -p no:cacheprovider /app/tests \
  --backend-mode=real --strict-acceptance -q --tb=short \
  --junitxml=/app/reports/known-fixes-real.xml
```

仅当上述服务是本次验收启动的独立测试环境时，结束后执行 `docker compose --profile test down --remove-orphans`。保留数据卷和报告，不删除业务数据。
