# 第三阶段第二批：共享预算与 Model Filter

本批不依赖 Bot Token 或模型 API Key。对应主开发方案 W05/W07/W10 的预算部分，基于官方 SDK 的公开 Model Filter 与日志接口实现。危险动作审批、完整 UI、供应商真实计价适配和生产 Runner 尚未在本批完成。

## 1. 已实现行为

- 价格版本不可变，模型配置标识与币种绑定；输入、输出以每百万 token 单价表示。金额在 PostgreSQL 使用 `NUMERIC(24,10)`，服务使用 Decimal，API 以字符串返回金额，拒绝浮点金额输入。
- 每租户/币种配置日额度、月额度和时区，通过 revision CAS 更新。时区建立后不能在线改变；额度不能调低到当前已结算与预留之下。
- 每次模型请求有独立 attempt。同一 attempt 重放预留不重复占额；不同参数冒用同一 ID 被拒绝。执行级调用次数从持久记录统计，取消的 attempt 也保守计数。
- 一次事务同时检查日、月额度，并写入两份周期账户的占额和唯一 attempt。两份账户表示两种限制，不能相加当作实际费用。
- 单次请求的 `reserved → in_flight` 转换提供一次发送许可；重复调用不能再次发送。发送前检查租户状态；IM 输入还检查 Binding、成员授权和 epoch。
- 只有尚未发出的 reserved 能直接取消。已发出但超时、取消、usage 缺失或计价维度不支持时进入待核算，继续保留额度。没有基于超时自动归零的清理器。
- 已确认 usage 只结算一次；相同 attempt 的不同结算证据被拒绝。实际成本超出预留时如实入账并阻断该租户/币种后续模型调用，提高额度不会悄悄清除这一阻断。
- 跨月恢复使用 attempt 原有周期和价格，新的请求使用新的周期。不同币种分别预留、核算，不隐式换汇。

核心代码：`trpc_service/governance/budget.py`、`model_filter.py`、`management.py`，表定义位于 `trpc_service/persistence/models.py`。

## 2. SDK 接线与当前能力边界

已读取官方固定提交 `f05797d9f9dff2461922b5985aeccc1b636b7c8d` 的公开实现对应文件：

- `trpc_agent_sdk/models/_llm_model.py`：`generate_async` 在 Model Filter 内执行 retry loop。
- `trpc_agent_sdk/filter/_run_filter.py`：流式 Filter 的下一层返回 FilterResult 封装，顶层才提取 rsp。
- `trpc_agent_sdk/models/_retry.py`：错误转换可能携带原始供应商异常；自动重试会重复发出请求。
- `trpc_agent_sdk/log/`：使用公开 BaseLogger / set_default_logger 接口替换原始诊断正文输出。

`attach_budget_filter` 要求显式 `ModelRetryConfig(num_retries=0)`，拒绝保留 SDK 隐式重试。供应商 HTTP 客户端的重试仍需在后续真实模型工厂关闭，不能仅凭这个检查宣称已控制所有网络重试。

ModelBudgetFilter 必须由可信供应商适配器提供 RequestEstimate：最终请求摘要、可证明的输入 token 上界与实际强制执行的输出上限。当前没有把通用字符串长度估算伪装成所有供应商的严格费用上界。测试使用确定性 LLMModel 子类，通过真实公开 `generate_async` 路径验证；没有连接收费模型。

当前计价契约只覆盖简单输入/输出 token。缓存、推理、工具使用、媒体等额外计费维度遇到未支持 usage 时保留待核算，不按零费用处理。未来适配器须在发出请求前拒绝不受支持的模型/参数，并纳入真实价格、工具 schema、回调修改和最终 wire payload 的核对。

SDK 日志适配器仅保留诊断级别和固定提示，避免 SDK 把供应商原始异常、参数或 extra 字段输出到日志；详细原因由平台审计与状态记录承载。该适配器不等于全部第三方 HTTP 日志、完整 SDK Trace 或内容脱敏已验收，这些仍属于 W05/W09。

现有 ServiceRuntime 的原生 Session fencing 生产门禁保持不变。本批没有将模拟 Worker 切成真实收费模型，也没有让模拟请求消耗真实预算。Memory/Summary/embedding 后台付费调用尚需接入同一账本；应用子额度、执行累计 token 上限、完整策略发布和真实供应商对账仍待补全。

## 3. 管理 API

以下接口继承已有 `/admin` operator 认证，用于开发运维和未来 UI。OIDC、浏览器会话及租户角色权限仍在 W10 待办中；operator Token 不能作为浏览器持久凭据。

| 接口 | 用途 |
|---|---|
| `POST /admin/tenants/{tenant}/model-prices` | 登记不可变模型价格版本 |
| `GET /admin/tenants/{tenant}/model-prices` | 价格列表 |
| `PUT /admin/tenants/{tenant}/budgets/{currency}` | 按 expected_revision 设置额度 |
| `GET /admin/tenants/{tenant}/budgets` | 策略、版本及 blocked 状态 |
| `GET /admin/tenants/{tenant}/budget-accounts` | 按周期列出额度、预留、结算与剩余 |
| `GET /admin/tenants/{tenant}/model-attempts?status=pending_reconciliation` | 查询请求与待核算状态 |
| `GET /admin/tenants/{tenant}/audit` | 查询预算策略和状态变更审计 |

金额示例为 `"daily_limit":"10.00"`，不是 JSON 浮点数。未知 `actual_amount` 返回 null，UI 不得显示为免费或零费用。价格、账户和 attempt 列表具有有界分页，并按 URL 中的租户范围查询。

没有公开“自行上报 usage”“把待核算改成零”“重置 blocked”的接口。后续人工对账与解锁必须补齐权限、供应商证据和审计后再开放。当前 `settle` 是内部可信调用，证据摘要只用于幂等冲突检查，本身不能证明供应商账单真实。

## 4. 数据库版本

当前 schema 版本从 3 升为 **4**，新增 `model_prices`、`budget_policies`、`budget_accounts`、`model_attempts`。

- 空数据库：`migrate` 初始化版本 4。
- 无版本的第二阶段数据库：既有离线升级流程直接升级到 4，并暂停旧身份绑定等待明确发布。
- 版本 3：停写并验证备份后执行既有 `upgrade-schema --offline --backup-id ...`。检查完整旧表结构以及无活跃通道 owner，再事务性添加预算表并更新版本；保留已有租户启用状态和配置。工具不能代替停写、备份与恢复验证。
- 普通启动和 `migrate` 不会自动修改已有版本 3。部分升级状态要求恢复备份，不能混合启动新旧服务。

本轮只升级/初始化了专用测试库，未升级运行中的第二阶段演示环境。
