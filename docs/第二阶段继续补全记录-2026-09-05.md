# 第二阶段继续补全记录

本轮按用户要求继续第二阶段，第三阶段不启动。导师给出的企微长连接方式与跨对话 UI/IM 参考另存于《跨对话参考与导师IM要求-2026-09-05.md》。不保存截图中的账号凭据。

## 本轮实现

| 工作包 | 本轮变更 | 验证 |
| --- | --- | --- |
| W03/W05 完成事务 | 新增 ExecutionCompletion，正常执行与恢复统一走完成例程。最终 Outbox 补齐、派生任务、运行中 attempt、Inbox 完成状态、完成审计同一平台 SQL 事务提交 | 注入审计写入失败，确认整个完成事务回滚；恢复后两类派生任务与成功状态一起可见；在 SQLite 与 PostgreSQL 验证 |
| W06 回复可靠性 | 同 session 不同入站消息的回复按入站顺序投递；前一条未知结果或未投递回复阻止后续。区分永久失败与可重试异常，并支持明确的 Retry-After 秒数 | 前一条尚无回复时，后一条已就绪回复不能抢跑；确认前一条后放行；120 秒限频与永久失败分类测试 |

| W07 审计边界 | AuditWriter.get 强制 tenant scope；metadata 仅允许明确的标识字段，拒绝任意正文、嵌套对象和数组 | 其他租户无法凭 audit_id 读取，嵌套敏感字段与任意正文拒绝 |
| W08 文件版本 | 新增 artifact_sequences 原子版本分配，artifact_metadata 保存 reserved/published/deleted；上传及元数据确认前不开放读取，已上传对象可经 recover_upload 完成发布 | 16 次并发上传取得 16 个唯一版本、内容不覆盖；真实 PostgreSQL + MinIO 验证；上传后 SQL 确认失败不可见，恢复后可读 |
| W08 内容与删除 | 读取将实际字节 hash 与 SQL 中的预期 hash 比较；删除先撤销可见性，计数器不回退；未登记旧对象拒绝覆盖 | 定向测试验证旧对象保持原内容 |

新增管理接口：

- `GET /admin/tenants/{tenant_id}/deliveries?limit=100&offset=0`
- `POST /admin/tenants/{tenant_id}/deliveries/{delivery_id}/retry`，请求体 `{"expected_attempt":5}`。仅接受 dead_letter，重置本轮重试预算，并保留投递 ID。真实 IM 不能保证接收端去重时，人工重试仍可能重复发送；这不等于外部 exactly-once。

## 数据库与部署

新增 `artifact_sequences` 表；已有表未增加或删除列。重建服务镜像后，先运行受控 `migrate` 初始化任务创建缺失表，再启动服务。没有执行清库、删卷、SDK 改写或第三阶段凭据配置。

S3ArtifactService 现在必须注入平台 Database。先前对象若不在本次元数据管理范围，写入会拒绝覆盖；不自动导入、重编号或删除。reserved 版本的诊断和恢复仍通过服务接口及数据库记录进行，目前尚未接入自动恢复扫描器。

本轮没有更新正在运行的主服务镜像，真实后端回归通过一次性测试容器加载当前源码执行。现有主服务运行状态不能作为新代码已部署的证据。
