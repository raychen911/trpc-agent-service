# 固定 SDK 的原子写保护扩展边界

2026-09-07 更新：用户已选择并授权第二种方案，在本服务仓库通过官方公开接口实现自有存储适配器。后续实施与验收见[服务自有原子 Session 与租户 IM 全链路](服务自有原子Session与租户IM全链路-2026-09-07.md)。下文保留为原生 SDK 缺口和当时范围的历史记录；不再表示只能等待上游修复。

## 已确认的缺口

用户已明确要求使用官方原始仓库，不使用本地二开或 fork。当前依赖固定官方 `trpc-group/trpc-agent-python` commit `f05797d9f9dff2461922b5985aeccc1b636b7c8d`。重新阅读该提交确认：公开 `SqlSessionService.append_event(session, event)` / `update_session(session)` 不接收 expected revision 或执行 fencing 前置条件；append 使用时间戳检测陈旧副本，update 可替换事件集合。Redis 公共接口同样未提供平台写前置条件。之前基于 fork 的判断和回归证据不作为本次最终基线。

本仓库的 `SessionCoordinator.commit` 只保护平台 session_events，不保护 SDK 的原生 Session。新增 metadata 仅建立执行追踪和恢复关联。不能采用“先查平台 SQL token，再调用 SDK 写入”来声称原子性。

## 最小扩展要求

以下为官方 SDK 所需公共契约的缺口说明，不是修改本地 SDK 或建立新 fork 的实施授权：

- 原生后端持有 session execution lease/单调 token。领取、续期、接管的身份包含 app/user/session，服务平台保留 Inbox 调度账本。
- create/append/update/delete 和摘要持久化接受同一个公开 WriteCondition，包含 owner、fencing token、expected revision、execution ID；仅通过 metadata 传值不算实现。
- SQL 在原生写事务中锁定租约/revision 行，比较并写入；Redis 使用原子脚本/事务把条件检查与事件、state、revision 更新绑定。旧 token 的写入必须明确失败，不能自动重载并覆盖。
- app/user scoped state 也必须具有跨 Session 的原子更新语义，不能只保护单个 Session 的事件。
- 返回原生 commit receipt：稳定 event ID、revision、execution ID、原生覆盖边界。重复提交同内容返回原 receipt，不同内容冲突。
- Summary 对原生输入边界 CAS，并能在摘要已写、平台确认未写时查回 receipt；无需复制 Runner/Session/Summary 内核到服务仓库。

## 扩展验收

两个独立进程，一个暂停至租约失效，另一个接管提交后，恢复旧进程并尝试 append/update/summary/delete；Redis/SQL 的真实内容和 revision 均不得被旧进程改变。还需并发首次建会话、同用户不同会话共享 state、确认丢失幂等重投、续期断连等用例。

## 变更范围

本次只修改 `trpc-agent-service`。`.upstream-sdk` 是未经修改的官方源码检出，仅供核对，不随服务提交或构建打包；本地二开项目不再作为 SDK 依赖或参考。上述能力若在官方公开接口中不可用，必须如实保留发布限制，不能把平台检查包装成底层原子保护，也不能擅自修改 SDK 基础组件。
