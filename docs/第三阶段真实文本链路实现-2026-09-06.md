# 第三阶段真实文本链路实现与验收边界

**范围修订：**本记录中的历史待办以用户最新要求和 [原始需求对照](第三阶段范围校准-原始需求对照-2026-09-06.md) 为准，不再强制全媒体、OIDC、12 组页面或商业系统接线。既有实测证据和生产限制保持其原有口径。

本批继续实施 W04、W07、W09、W13，完成可验证的文本执行链路，**不表示第三阶段全部完成**。管理 UI、持久审批、媒体处理、生产并发写保护仍以开发进度表为准。

## 1. 执行路径

```text
企微 WebSocket / Telegram Update
  → 单次随机单聊口令 → 隔离测试租户和精确 actor 授权
  → IMIngress：receipt + Inbox + 加密 reply context
  → DurableExecutionPipeline + SessionCoordinator
  → 官方 LlmAgent / Runner + 原生 SqlSessionService
  → ModelBudgetFilter → OpenRouter → usage.cost 结算
  → 原生 Event → Outbox → IMDeliveryWorker → 真实渠道回执
```

`trpc_service/channels/acceptance.py` 每次创建新目录，只接受一条精确匹配的私聊口令，一个进程执行，关闭工具。Git 忽略目录 `.secrets/acceptance/<run_id>/` 内保留两个 SQLite 文件，分别保存平台和 SDK 原生 Session 数据。入口拒绝复用旧目录，不是可恢复生产部署或双 Worker 原子写验收。

联调用现有业务模块完成真实事务，不手工插入模型结果或伪造渠道回执。Summary/Memory 派生任务会持久入队，但入口不消费它们，报告明确记录 `post_turn=not_executed`。口令授权只用于隔离联调，不能充当生产成员注册。

## 2. SDK 公开接线

- 使用 `OpenAIModel(http_client_provider_factory=...)` 安装平台 HTTPX 客户端。上游会覆盖 `client_args.http_client`，不能通过后者接入回执钩子。
- 官方 LlmAgent 内部以 `stream=True` 调用模型，外层 `RunConfig.streaming=False` 不改变这一点。本批支持 JSON 与 SSE 用量响应，缓冲供应商响应后解析原始 usage，SDK 负责原生 Event 转换。
- 公开 Model Filter 与 HTTPX 钩子通过每调用独立的 ContextVar 关联，避免并发串账。不修改 SDK、不访问私有 Session 属性。

当前 SSE 缓冲服务于最终文本验证，不算完成 IM 实时增量快照或卡片交互。

## 3. 真实费用契约

模型固定为 `deepseek/deepseek-v3.2`，入口固定为 OpenRouter。启动时从公开模型目录获取上下文长度；预留整个上下文窗口的输入费用，不将近似 tokenizer 当作硬上限。输入/输出价格上限分别为每百万 tokens 1/2 USD，实际请求必须携带相同 `provider.max_price`，并关闭 fallback、reasoning 及 SDK/HTTP 重试。

一次联调最多一次模型调用、128 输出 tokens，测试租户日/月额度均为 0.50 USD。`openrouter-text-cap-v1` 是预留价格上限，不是供应商实际单价。HTTP 钩子在发出请求前校验目标地址、模型、限制、单次调用许可和内容类型；工具、插件、额外路由、图片/文件须使用其他计费契约。

结算使用供应商原始 `usage.cost`，核对 SDK 与原始响应的输入/输出 token 数。Decimal 解析和向上保留 10 位小数避免二进制浮点金额误差。重复结算发生金额/证据变化时拒绝；超出预留时记录实际金额并阻止后续调用。缺失费用、冲突 usage、取消、错误或网络结果不明时保留预算待核算。最终模型响应必须等结算成功才交给 Runner。

供应商总费用语义依据 [OpenRouter Usage Accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting)，缓存等费用以供应商回执为准。完整发票、充值费用与其他供应商计价尚不在本批范围。

预算 SQL 在线程中运行，保持事件循环和续租响应；取消会等待事务完成，再释放未发送预留或保留已发送费用。重复取消不会遗失正在执行的数据库事务。

## 4. 追踪、审计与隐私

协议测试验证 `im.callback → worker.execute → session.append → model.provider_response → im.reply` 共用 Trace ID。Inbox 持久化活动 Trace ID；执行完成审计记录 actor、通道、request_id、trace_id，费用审计关联同一执行和预算 attempt。精确金额以 NUMERIC 账本为准，审计保存 attempt/amount/currency 引用，不用历史浮点审计 cost 列作为财务账本。

报告只导出状态、token、金额和计数，不导出消息正文、IM 账号、Secret、API Key、原始供应商异常和加密上下文。Tool、Memory、Summary 的完整 Trace、指标看板与审计导出仍待联合验收。

## 5. 操作

在仓库中分别运行所需通道，不要让其他进程同时连接同一测试机器人：

```powershell
.venv\Scripts\python.exe -u -m trpc_service._cli wecom-e2e --secrets-file .secrets/im.json --test-timeout 600
.venv\Scripts\python.exe -u -m trpc_service._cli telegram-e2e --secrets-file .secrets/im.json --test-timeout 600
```

认证后把终端给出的整行随机口令发到机器人单聊。超时停止，不自动重试模型或未知投递。Telegram 检测到已安装 webhook 时退出，须按部署方案显式切换模式。

结果为 `reports/live-<channel>-acceptance-<run_id>.json`。`passed` 只覆盖报告声明的单进程文本范围；企微协议 ACK 不代表已读，尚未获得人工确认时 `human_read_confirmation=false`。
