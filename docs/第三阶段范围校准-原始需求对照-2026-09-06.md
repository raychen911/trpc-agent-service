# 第三阶段范围校准：严格按原始需求实施

2026-09-06 用户明确要求：“不用拓展额外的内容，严格按原来的需求做就可以”。本文件修正此前开发方案中过度扩展的必做项。需求基准是服务仓库 README 的“具体要求、交付物、验收标准”，以及用户已经明确要求的管理 UI 和真实 IM 联调；不从示例或参考仓库推导新增业务。

## 1. 需求对应关系

| 原始要求 | 本次保留的范围 | 不作为完成门槛的扩展 |
|---|---|---|
| 多租户、节点化部署、配置和数据/工具/密钥隔离 | 租户模型、可信路由、共享状态、必要后台授权、可运行部署及隔离验证 | 固定五种角色、复杂组织层级、指定身份提供方 |
| Tool 调用、Filter 工具白名单、危险工具确认、失败处理 | 使用本项目实际可执行工具验证调用、授权、确认和结果；优先复用文件/知识工具 | 接公司订单、真实退款、外部工单系统；新增业务产品 |
| IM Channel Adapter 至少两类，包含微信或企微 | 保留企微，完成另一类通道的接入差异说明和约定的真实联调；第二通道待用户选定 | 同时实现所有备选 IM；每个通道同时提供所有接收模式 |
| Event 转 IM 回复、流式或卡片；考虑媒体、长度、频率、异步、撤回、重试 | 可靠文本基线；能力矩阵说明支持方式、限制及降级；不支持的图片/文件等明确处理并测试 | 要求每个通道同时完整支持图片、文件、流式、卡片、编辑、撤回；语音视频理解 |
| 用户身份映射、租户/工具隔离、IM 用户权限校验、Admin API | 后端逐请求鉴权和资源归属校验；管理 UI 必要登录及租户授权 | 强制 OIDC/ZITADEL、完整 IAM 产品、委派审批/双人审批 |
| 预算、脱敏、模型/工具/投递/成本/Session 指标 | Filter 实际生效，明确统计和计价口径，保护日志/Trace/错误出口 | 同时支持所有模型供应商计费、独立财务核算产品 |
| Trace 贯穿 IM、Runner、Tool、Session/Memory、回复；审计指定字段 | 对实际执行链路采集、关联、验证；区分已实现与缺失 | 为展示增加无需求来源的独立分析系统 |
| Session/Memory/Summary/Artifact/Knowledge/Audit 数据抽象及后端切换 | 保留原要求的六类资源职责、至少三类后端说明、数据同步和迁移方案及相关实现 | 为完成题目额外加入自然语言 embedding 产品、所有后端在线双写搬迁 |
| 故障降级、灰度回滚、容量评估、最小部署和生产推荐方案 | 保留设计、可运行部署和相应验证；如实报告未知结果与生产限制 | 无依据的生产 SLO 承诺、所有极端故障窗口的无限恢复保证 |
| 用户明确要求最终有 UI | 复用已有 API，提供原需求对应的配置、租户/通道管理、会话检查、治理/预算/审计、运行状态入口 | 强制拆成 12 个页面；客服接管工作台、可视化编排等产品扩展 |

原 README 的“例如”用于举例，“说明/考虑”要求有具体设计和边界，不能一律提升为“全部功能必须实现”。同时 README 要求提供基于设计的代码；收敛范围不意味着用文档替代核心实现，也不削弱租户隔离、确认、预算或密钥保护。

## 2. 修订后的开发与验收清单

- [ ] 对照原 README 逐条核对多租户、节点部署、多后端数据同步、IM、治理监控和故障恢复，提供实际代码及证据。
- [ ] 至少两类 IM，包含微信或企微；明确账号绑定、验签/认证、身份、单聊群聊 scope、去重和平台限制。完成用户已要求的真实联调，协议测试不冒充实测。
- [ ] 完整链路实际包含可执行 Tool，以及 Session/Memory 读写；可复用仓库资源工具，不以接入商业系统作为门槛。
- [ ] 工具白名单、必要危险操作确认、IM 授权、预算和敏感信息保护有效；对重复、越权及失败给出正确处理。
- [ ] 原要求指标、全链路 trace_id/request_id 和审计字段有明确实现及验证。
- [ ] 完成用户要求的可用管理 UI，页面可合并；服务端权限检查、秘密不暴露和实际 API 连接必须有效。
- [ ] 补齐架构文档、架构图、核心时序图、数据模型、同步/幂等说明、至少三类后端方案、至少八项风险及代码交付。
- [ ] 报告区分设计、代码、协议测试、真实后端、真实 IM 和生产可用性；不能以范围收敛为由将原生 SDK 写保护等实际缺口标为通过。
