# 本地运行与验收

## 1. 准备

本地应用使用主机 Python 3.12 和 uv，不创建应用 Python 容器。Docker Compose 只运行 PostgreSQL + pgvector、Redis、SeaweedFS 和可观测组件。

```bash
cp .env.example .env
```

只需先在 `.env` 填写 `DASHSCOPE_API_KEY`。其他本地密码和平台 Bootstrap Token 由 `start.sh` 首次生成到已忽略的 `.secrets/`，不得复制到代码、文档或截图。

默认 `TRPC_SERVICE_SESSION_CACHE_URL=redis://127.0.0.1:6379/0`，用于近期对话缓存；TTL 和事件上限可在 `.env` 调整。关闭该配置或 Redis 暂时不可用时会回源 PostgreSQL，不影响会话事实。

## 2. 启停

```bash
./start.sh
```

脚本会同步锁定依赖、构建 Python 制品、启动基础设施、执行 Alembic Migration 和独立的存储准备步骤，并启动 Gateway、Channel Runtime、Worker Supervisor 和默认两个独立 Worker。向量表和对象桶由准备步骤创建，运行进程只检查兼容性和访问权限。手工部署时，迁移后需执行 `uv run python -m trpc_service.storage.provision`，再启动服务。服务就绪后访问：

- 系统管理端：`http://127.0.0.1:8000/admin`
- 租户管理端：`http://127.0.0.1:8000/tenant`
- 健康检查：`http://127.0.0.1:8000/health`、`/ready`
- Grafana：`http://127.0.0.1:3000`，用户名 `admin`，密码读取 `.secrets/grafana_admin_password`
- Prometheus：`http://127.0.0.1:9090`

首次进入系统管理端时读取 `.secrets/admin_bootstrap_token`，使用 Bootstrap Token 初始化平台数据；再创建租户及该租户唯一的管理员账号。租户管理员随后登录 `/tenant` 创建 Agent、配置 IM、维护知识库与 MCP 连接。

```bash
./stop.sh
```

普通停止保留数据。仅在确认测试数据可以全部删除时执行 `./stop.sh --volumes`；该操作会清空本地 PostgreSQL、Redis、SeaweedFS 和监控数据。

## 3. 配置顺序

1. 平台管理员创建模型目录、平台模型凭据和租户 Model Profile。
2. 平台管理员创建租户，并为该租户创建唯一管理员账号。
3. 租户管理员创建 Agent，选择可用 Model Profile，显式授权 Tool、Skill、MCP Tool 和知识库。
4. 租户管理员填写企业微信 Bot ID/Secret 或飞书 App ID/App Secret，并启用 Binding。
5. Channel Runtime 自动发现配置并建立长连接，不需要把租户 IM 密钥写入 `.env` 或 `.secrets/`。

Agent 必须同时满足“已启用、已绑定可用模型、配置快照有效”，IM Binding 才允许创建或切换到该 Agent。这样企业微信、飞书及后续 Adapter 使用同一就绪校验，不会把配置错误延迟到消息处理阶段。

```bash
./coverage.sh
./build.sh
```
