# 跨对话参考与导师补充

当前执行顺序：先补齐第二阶段，再开展第三阶段。此文件保存参考资料，不表示第三阶段已开发或验收。

已读取历史任务「查找支持 IM 后端的多租户项目」（任务 ID `01a065ab-372d-7603-9020-aa1023e5db0b`），原讨论给出的参考分工如下。这是历史讨论的摘记，不是对项目最新功能的重新核实。

| 方向 | 历史参考 | 使用范围 |
| --- | --- | --- |
| IM Adapter | TGO、LangBot | 多账号、消息格式、媒体、回复与限频 |
| 账号与会话管理 | Chatwoot | Account、Inbox、Contact、Conversation、人工接管 |
| 配置界面 | Dify、FastGPT、MaxKB | Agent、模型、知识库与工具配置交互 |
| 配置控制面 | Kubernetes Controller | 期望状态、实际状态、版本发布与协调 |
| 可靠消息 | Debezium Outbox、Kafka 分区思路 | 事务消息、去重与会话顺序 |
| 租户身份 | Mimir、ZITADEL | 可信租户传播、组织与授权 |

这些方案用于参考各自子系统；不替换官方 tRPC-Agent-Python 运行内核，不引入本地二开 SDK。

导师截图及用户补充确定企业微信通道为智能机器人 API 模式的长连接：工作台 → 智能机器人 → 创建机器人 → 手动创建 → API 模式 → 使用长连接 → 获取 BotID、BotSecret。两项凭据使用 SecretRef 管理，文档不保存截图中的账号或秘密。

第三阶段仍须覆盖至少两类 IM，其中包含微信或企业微信。需要逐项说明认证差异、消息与 Agent Event 转换、单聊和群聊隔离、长度和限频、流式或异步回复、图片文件、撤回及失败重试。长连接身份认证与 HTTP webhook 验签属于不同接入方式，不能机械套用同一接入流程。
