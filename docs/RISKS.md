# 生产风险与缓解措施

以下风险覆盖多租户、IM 接入、存储、模型调用、工具执行和运维恢复场景。

1. **Redis 故障**：使用 Sentinel/Cluster 或云托管 Redis，设置超时、重试和降级健康状态，禁止在生产中静默回退到进程内内存。
2. **PostgreSQL 故障**：配置连接池、事务超时、重试和就绪探针；队列可短暂缓存可恢复工作，但必须记录审计错误。
3. **IM 重复投递**：按 `tenant_id + channel + account_id + external_message_id` 做幂等，重复消息直接复用已完成结果。
4. **Session 并发写冲突**：采用 event sourcing、乐观锁和有限重试，必要时回队列重放。
5. **模型 429 / 5xx / 超时**：指数退避、熔断、预算预留、错误兜底回复和审计记录。
6. **工具或 MCP 被滥用**：租户白名单、黑名单、审批规则、超时和隔离凭证，所有工具调用写审计。
7. **密钥泄露**：配置仅保存 `secret://` 引用，运行时解析；日志、Trace 和错误报告统一脱敏。
8. **跨租户访问**：所有表、Key、索引和权限检查强制带 `tenant_id`，并增加跨租户回归测试。
9. **IM 平台限流**：通道级限流、消息切分、异步投递和重试队列，避免直接打爆平台配额。
10. **配置回滚失败**：配置版本不可变，发布前校验，回滚只切换 active version 指针。
11. **知识索引漂移**：导出、导入、抽样 top-k 比对和回滚窗口内保留旧索引。
12. **Worker 出队后崩溃**：使用 processing 列表、可见性超时、重试计数和死信队列。
13. **补偿队列积压**：监控 pending 数、最老任务年龄和失败率；按租户限速重放，超过阈值告警并保留人工 replay 入口。
14. **危险工具审批 token 滥用**：approval token 按租户签名，审批请求必须先写入 Session event；生产应通过 Admin/IM 权限校验签发，日志中不记录 token 明文。
15. **撤回事件乱序**：撤回只追加 `message_revoked` 事件并保留审计，不物理删除历史消息；无法匹配目标消息时记录 target id 等待后续核查。

## 风险优先级

最高优先级是跨租户隔离、密钥泄露、幂等失败和 Session 并发冲突，因为这些问题会直接影响数据正确性和生产安全。其次是模型故障、IM 限流和存储故障，它们主要影响可用性和延迟。
