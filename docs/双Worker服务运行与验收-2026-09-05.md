# 双 Worker 服务运行与验收

日期：2026-09-05。本文记录本次新增的服务闭环，不替代第二阶段补全方案 W01—W12 的完整验收。

## 交付边界

当前可以独立启动 **显式 simulation 模式**：Gateway、两个持续消费的 Agent Worker、独立 Outbox Dispatcher、独立 Post-turn Worker，共享 PostgreSQL、Redis，使用真实固定版本 tRPC Runner/Session/Memory 和确定性模型。Qdrant/MinIO 保留在 Compose 中，已有后端测试继续执行；本次模拟 Agent 不使用工具或 RAG。

当前固定官方 `trpc-group/trpc-agent-python` 提交 `f05797d9f9dff2461922b5985aeccc1b636b7c8d`，不依赖本地二开或 fork。之前基于 fork 的报告不是最终验收依据。

这不是完整生产双 Worker 发布。重新核查官方 SDK 后，仍未发现原子 fenced Session 写入公共接口。`GuardedSessionService` 记录 execution/token 元数据，但不会在底层事务里拒绝旧 owner。平台租约续期、取消旧任务、平台事件 CAS 都不能替代它。因此未设置 `TRPC_RUNTIME_MODE=simulation` 时，运行时明确拒绝启动，没有模型或存储 fallback。

## 运行

```bash
docker compose up -d --build gateway worker-1 worker-2 dispatcher post-turn
docker compose ps
python tests/integration/dual_worker_acceptance.py
```

Compose 使用已有命名卷，初始化任务只创建缺失表，不清理数据。应用启动检查表及列是否存在，不自行建表。代码与数据库结构不匹配时应停止并检查，不能通过删卷消除错误。

模拟配置为 `deploy/simulation-tenants.json`；这是运维维护的可信配置文件，不能交给外部回调修改。模拟 API 使用 `TRPC_SIMULATION_TOKEN`，HMAC 身份由稳定的 `TRPC_IDENTITY_KEY` 生成。Compose 中的示例值仅用于本地验收。模拟接口允许持有测试令牌的操作者查看测试数据，不是租户生产查询 API。

示例输入：

```bash
curl http://localhost:8080/simulation/inbound \
  -H 'Authorization: Bearer simulation-access-token-change-for-your-environment' \
  -H 'Content-Type: application/json' \
  -d '{"channel":"wecom","webhook_public_id":"callback_acme","external_message_id":"demo-1","external_user_id":"demo-user","conversation_type":"direct","text":"记住订单 42","received_at":"2026-09-05T12:00:00Z","request_id":"demo-request-1"}'
```

接受成功返回 `inbound_message_id` 和 `execution_id`。携带同一测试令牌查询 `/simulation/messages/{inbound_message_id}`，可以查看业务状态、真正收到的回复、Outbox 状态和派生任务结果。`wecom` 在这里是标准化契约字段，不代表已完成企业微信验签或实际投递。

## 执行与恢复语义

- 首次接受固定完整 route；业务幂等摘要排除 request_id、received_at、trace 和新解析的配置版本。同 ID 不同内容报 409。
- PostgreSQL Inbox 使用行锁和 `SKIP LOCKED`；同 partition 未完成的早期消息阻止后续领取。每次领取有独立 owner，进程内并发任务不会重用会话租约身份。
- Inbox 与 Session 租约周期续期。配置并发、租期、排空时间分别为 `TRPC_WORKER_CONCURRENCY`、`TRPC_LEASE_SECONDS`、`TRPC_DRAIN_SECONDS`。SIGTERM 停止领取，最多排空 20 秒；超时取消，保留持久工作等待接管。
- 原生事件在 SDK append 前标注 execution/token。真实最终回复已落库、平台投影未完成时，从原生 active/historical events 恢复投影，不重跑模型。平台已有完整事件、Outbox 部分落库时，按稳定 part ID 补齐。
- 成功的正常路径和恢复路径都幂等补齐 Summary/Memory 任务，然后完成 Inbox。当前通过补偿恢复跨事务间隙，尚未把所有平台完成写入合成一个 SQL 事务。
- 已开始执行但没有可证明的最终结果时，不盲重跑；达到有限恢复次数后进入 `unknown_outcome`。这类任务需要对账，不能声称任何故障都自动恢复成功。
- Dispatcher 使用稳定 Outbox row ID 作为发送键。接收端单独持久去重，确认后再标 delivered。发送失败最多重试 5 次，之后 dead_letter；同消息后续分片不会越过失败分片。尚未实现跨消息会话投递排序、Retry-After 和人工死信重放接口。
- Post-turn 使用原生 Session，不拿脱敏通道文本重建事实。Memory 收集原生历史和当前非摘要事件；Summary 通过 SDK 公共 summarizer 生成，记录原生输入 event IDs 与平台调度水位。旧任务在会话租约下合并到当前输入边界；进程重启可从原生摘要元数据修复平台水位。完整的旧 owner 原子拒绝仍依赖 SDK 扩展。
- 三类消费循环在数据库异常后退避继续运行；不可确认副作用结果保持 unknown，不以重试掩盖风险。当前模拟运行时拒绝配置工具、RAG 或真实模型。

Gateway `/health/live` 不查询数据库，`/health/ready` 查询数据库。Worker/Dispatcher/Post-turn 的 `healthcheck` 读取事件循环持续更新的本地心跳及 SQL 就绪状态。该检查未覆盖所有可选后端；本地同时启动多进程时需分别设置 `TRPC_HEALTH_FILE`。指标采样保留最近 2048 个值、最多 4096 个序列，累计 count/sum 与窗口分位数分开。

双进程运行 ID 为 `84809620fd3c`，100 条突发及轮询确认总耗时约 4.66 秒。模型为确定性模拟，未调用付费模型，未将此结果换算为生产容量。Post-turn 成功包括按保留最近事件策略无需压缩的短会话；实际多轮摘要压缩和 Memory 写入由单独 Runtime 用例验证。

```bash
python -m pytest -q --strict-acceptance --junitxml=reports/worker-official-local.xml
python -m flake8 trpc_service tests
git diff --check
docker compose build e2e
docker compose run --rm -v ./reports:/app/reports e2e -m pytest -o addopts= -p no:cacheprovider /app/tests --backend-mode=real --strict-acceptance --junitxml=/app/reports/worker-official-real.xml -q
python tests/integration/dual_worker_acceptance.py
```

双进程验收脚本只操作本 Compose 的 worker-1、worker-2、post-turn 和带唯一名字的故障容器；结束后恢复这些消费者。它不会删除数据库或卷，每次测试使用独立消息/用户身份。故障点通过原生 append 成功后的进程间输出屏障定位，再终止一次性容器，不依靠随机 sleep 碰撞。

运行本地命令前必须激活本项目 `.venv`（Windows 也可直接用 `.venv/Scripts/python.exe`），或在干净环境按 pyproject 安装。服务启动和测试入口都检查 SDK 来源；系统 Python 中原有本地 fork 会被拒绝，不通过环境变量偷偷切换基础组件。

官方基线原始证据：`reports/worker-official-local.xml`、`reports/worker-official-real.xml`、`reports/dual-worker-acceptance.json`。双进程报告同时校验官方仓库 URL 和固定 commit，并记录镜像 ID；100 条突发耗时不是固定资源稳态容量或生产 SLA。`worker-local.xml`/`worker-real.xml` 是切换官方 SDK 前的中间记录，不可作为最终验收。
